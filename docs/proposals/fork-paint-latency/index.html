II. Root-Cause Code Walkthrough (file:line)

Algorithmic Complexity & I/O Multipliers

Correctness Bug Uncovered in Real PTY: Empty Landing Page on Deep Interior :fork <id>:<turn>

In internal/cli/livelog_bridge.go:840-874, livelogTurn.retarget calls t.client = t.client.CloneBelow(base). When viewing the live tail of a 518-turn figaro (which retains only the last ~30 messages, turns 506..518) and running :fork ace9cc9f:104, CloneBelow(104) retains zero messages (kept == 0). Lines 863-866 then set floor := base (104) and check if first, ok := t.client.FirstMissing(); ok && first < floor. On an empty aria.Client, FirstMissing() returns (0, false), leaving floor = 104 and returning seedPlan{kind: seedTail, from: 104}. seedRead (internal/cli/command.go:878) calls ReadBeforeFloor(tail, floor=104) on a child whose turns run 1..103, receiving 0 parts, skipping setMoreBefore (only run for seedWindow at command.go:1086), and painting the blank new-conversation landing page (===) over a 200.6k-token fork. Reproduce: open any 100+ turn figaro at tail and run :fork :20.

1. Off-Screen Glamour Layout + Double Goldmark AST Parse

55 to 129 ms
internal/cli/transcript_window.go:411-419 · transcript_index.go:175 · internal/render/markdown.go:84-105

Before emitting a single PTY frame, renderFrame() calls t.settle(), which runs buildIndex() up to 4 times while tuneTail() expands the window until it fills pageRowBudget() = 800 rows (up to 30 messages). On large engineering turns, that synchronously renders 984 to 1,225 terminal rows (22 to 36 messages) through Glamour even though the 120x40 viewport displays only 37 body rows. Worse, markdownRenderer.Render calls holdHyphens(source) (markdown.go:85, 99), which runs a full md.Parser().Parse AST walk whenever the markdown contains - (virtually every assistant message), and then parses the full AST a second time on line 86.

2. XWAL Multi-Channel Branch + Coherent Birth fsync

53 to 98 ms
internal/store/xwal_store.go:447-518 · figwal/xwal

XwalStore.forkWithKind acquires the store-wide s.mu mutex across both s.trunks.ForkTail / forkAtLocked (39 to 83 ms creating branch directories and updating layout metadata across a 2,479-node store) and writeBirth (xwal_store.go:484-518), which writes the birth form patch, genesis input IR message, and stampBirth (aria_id) before blocking on x.SyncCoherent() (14 to 17 ms NVMe fsync).

3. Interior :N Triple History Read + @topology fsync

+80 to 108 ms
internal/angelus/topology_handlers.go:205-229, 296, 391, 447-457 · store/topology_form.go:23

An interior :N fork reads and decodes the conversation's IR history three separate times: (a) forkPointOf (line 205) calls log.Read() on all 2,500..2,866 parent records to map turn N to atMainLT (21..33 ms); (b) heldBy(child) (line 447) calls log.Read() over 1..atMainLT to fold token/message counts into _meta (8..24 ms); and (c) AriaReader.serverFor(child) reads 1..atMainLT again on attach. When atMainLT sits in an ancestor trunk, handlers.place (line 296) also mutates @topology and waits for a second synchronous WAL fsync (36.5..50.5 ms).

4. Cold AriaReader Full-History Projection & Missing Singleflight

33 to 83 ms
internal/angelus/reader.go:103-146 · internal/cli/command.go:689-692 · figaro/agent.go:239-250

Even when the parent is warm in AriaReader.servers, a newly forked child has a fresh ID, so serverFor(child) starts cold: it loads all 2,866 IR entries (20..31 ms, sharing decoded segments via irCache when warm), runs proj.Turns(msgs) over all 279..671 turns (2..9 ms), runs formdelta.PerRecord (7..17 ms), calls ra.srv.Restore(turns) (15..24 ms), and recomputes metrics, sending 166..201 KB of JSON over the socket just to populate a 30-message tail window. Furthermore, serverFor unlocks r.mu at line 112 with no per-figaro lock, while retarget fires seedMetrics and seedSubject concurrently. Waking the fork into NewAgent repeats the entire O(msgs) projection a second time (+58..62 ms).

5. Sequential Per-Study Libretto fsync + Form Drop/Re-open

5 to 22 ms
internal/store/xwal_backend.go:561-568, 656-672 · internal/store/libretto.go:116-143

XwalBackend.ForkWith calls inheritStudies(child), which opens child's bound form and iterates sequentially over studiesOf(snap), calling lib.Retain(child) on each studied form. Every Retain submits a privileged patch to @libretto::<id> and blocks on SyncThrough (~4.5 ms per study: 15.4..21.8 ms for 3..4 studies). Next, line 564 calls b.dropForm(child) and line 565 calls stampCommitted(child, stamped), immediately reopening and replaying child's form channel from disk a second time.

6. O(history) stumpFormLog Replays & Watermark Patch Fallback

10 to 176 ms
internal/store/topology_form.go:49-75 · internal/store/form.go:173-180, 269-284

xwalFormLog implements FormBaseLog (watermarked segment headers), but stumpFormLog (backing @topology and every @libretto::*) does not: cold open of @libretto::b349567d (1,985 records) takes 176.5 ms of single-record ReadAt calls during daemon boot (list.warm p50: 814 ms). Conversely, on forms that do have a segment watermark (st.trimmed > 0), Form.PatchesBetween (form.go:273) falls back to patchesFromLog on every historical record below st.trimmed, causing formdelta.PerRecord to issue 70..90 separate XWAL open+read cycles in a single page build.

III. Instrumenting Fork & Fork-to-Paint in figscope

OTLP Spans, Metrics & Clock-Skew Invariants

Why Existing Telemetry Is Blind to Fork Latency

  • The 151.1 ms key_to_paint Clamp (internal/cli/keypaint.go:86): opensPit("fork") returns false because "fork" is in overlayVerbs (command_router.go:73, 95). Thus t.awaiting stays false. Whenever :fork takes longer than progressDelay = 150ms (command_router.go:539), an intermediate frame paints on the outgoing parent figaro at 151.0..151.2 ms and calls t.answerKeys(), recording ~151 ms in figaro.pager.key_to_paint even when the fork actually paints at 260..360 ms!
  • No Daemon Span on angelus.fork (topology_handlers.go:235): handlers.create opens figOtel.Start(ctx, "angelus.create"), whereas handlers.fork emits zero OTel spans and carries no traceparent field on rpc.ForkRequest or rpc.ReadRequest.
  • figscope Ingest Drop Filter (~/dev/figscope/model.go:54): keptSpans only admits figaro.qua, figaro.round, figaro.methods, cli.submit, and decide. All other spans are dropped at ingest in otlp.go:58, tail.go:66, and forward.go:61.

Pitfalls to Avoid in Production Telemetry

  • Clock Skew Across CLI & Remote Door: Never subtract a daemon span timestamp from a CLI span timestamp when assembling waterfall layers in derive.go. Stamp fork.rpc_sent and fork.rpc_acked on cli.fork using the client's monotonic clock, and scale angelus.fork internal sub-events proportionally inside that bracket (or relative to angelus.fork.StartN).
  • Optimistic vs Contentful Paint: Record both hop.optimistic_paint (from CloneBelow) and fork.first_paint (after seedSubject + renderFrame with t.index.total > 0 || t.landing()), tagged with cli.empty_landing: bool so regressions like the :104 bug trigger an immediate alert.
  • Series Cardinality in SQLite points (figscope/store.go:387): Bucketize size attributes on histograms (size_bucket: "lt200" | "200_1k" | "gt1k", interior: bool, cache: "cold" | "warm") rather than attaching raw figaro.id to metric points! Keep raw figaro.id and wire_bytes on cli.fork / angelus.fork spans only.
