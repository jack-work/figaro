# Troupe: one owner's figaros, pooled across machines

**Status:** agreed with Gluck, 2026-10-18 (draft 4, after the turn 138-139 threads). Steps 1, 3, 4, 5, 6 and 7 are built on the `impresario` branch. Changed in step 4, and Gluck should see it: a joined node holds a leaf only, not an intermediate (section 3).

## 1. What it is, and what it is not

A troupe is one owner's set of figaro nodes: their desktop, their laptop,
spain, a hosted node. It has one root of trust, one identity provider, and one
policy. Arias live on a home node, and any node reaches any aria (the F2
routing that shipped in 0.44 and the F3 move that ships next).

It is not federation. Federation means separate owners whose servers
interoperate with partial trust (email, Matrix). That may come later, as a
layer between troupes, and keeps the word.

The goal this serves: install figaro, `figaro troupe join <name>`, and the
new machine's arias join the pool. Figaros anywhere in the troupe can then be
granted the right to run as you on that machine.

## 2. The parts

| part | what it is |
|---|---|
| node | one figaro daemon with one store. It has a node id (F1) and a node certificate. |
| owner | the human who controls the troupe. Today, Gluck. |
| provider | what figaro asks to sign node certificates, list members and name issuers. `static` (all in config, no service) or `figaro` (any figaro node serving it on its door); others later. |
| identity issuer | where callers' tokens are verified (OIDC: issuer, JWKS, userinfo). Authelia for spain's troupe. Not necessarily a figaro node. |
| membership | the set of signed join and revoke entries naming the nodes, their doors and certificates, plus the signed troupe policy. |

## 3. Trust

```
troupe root key       1Password; used rarely
   └── node intermediate   ~1 year, on the nodes the owner gives one
          └── node certificate   one per node, ~7 days, auto-renewed
```

- The root signs node intermediates, nothing else. It is needed to create the
  troupe, to give a new node its intermediate (once a year per node), and to
  recover from a compromised node. It is read from 1Password at that moment (`op read` piped
  into `figaro troupe root ...`) and never written to disk.
- A node signs a joining node's certificate only if it holds an
  intermediate, for a principal that holds `join`. `troupe create` and
  `troupe intermediate` give one; `troupe join` does not, because issuing an
  intermediate needs the root and the root stays offline. A joined node
  holds a leaf only. It renews the leaf from a node that holds an
  intermediate, over the node door and on its current leaf, and cannot
  sign anyone in until the owner runs `troupe intermediate` for it. Asked
  to sign, it refuses and names the nodes that can. A node whose leaf
  expires joins again.
- A node certificate carries the node id as a URI SAN and serves both sides of
  the node door, as F2 already expects.
- A compromised node can sign new nodes. Every signature is recorded in
  membership (below), so it is visible, and revoking that node's intermediate
  revokes everything it signed.

## 4. Membership

A set of signed entries, not a document with one writer:

```
join   {node id, door, owner}  signed by the admitting node's intermediate
leave  {node id}           signed by the node's own key
revoke {node id}           signed by the root; also voids the joins that node's
                           intermediates signed
```

- Nodes gossip their sets on the node door and merge by union. A leave or revoke always
  wins over a join of the same node. Join and revoke commute, so no ordering or
  consensus is needed.
- Stored as a form every node mirrors: durable, inspectable with `figaro form`,
  and the audit log of who admitted whom.
- The troupe policy is a separate document, versioned and gossiped the same
  way; a higher version replaces a lower. A principal holding `admin` on the
  troupe changes it through any node, and that node signs the version with its
  intermediate and records which admin asked. A compromised node could forge a
  version, as it could already act as any peer; the record shows which node
  signed it and revoking its intermediate cuts it off. An out-of-band admin
  panel as the bottom turtle can come later if needed.
- Liveness: node certificates last about 7 days and renew automatically, so a
  node offline past that is refused by every peer without anything being
  signed. Calls to its arias fail with "node X unreachable" meanwhile, and
  `troupe ls` marks nodes that have gone quiet. Known limit, accepted: an aria
  homed on a node that never returns is lost with it (no replicas); move it
  first, or a later "evacuate".

### Static mode

With the `static` provider nothing gossips: members, CA files and issuers are
written in each node's config (for Gluck's estate, by spain-flake and
cheroot-config). The file carries a version; peers compare versions on the
node-door handshake and log a mismatch, and `troupe ls` shows drift. A node
missing from another's file is refused by it.

### Policy

The troupe policy is the single shared policy every node applies. A node's own
`policy.toml` stays local and applies only on that node; nothing is merged on
join. Either may grant, with two rules: `use` on `sandbox:local` (running as
the user on that machine), and `admin` on the troupe itself (changing its
policy, revoking, leaving), are granted only by local policy. (Step 6.)

A troupe grant applies on a node only as far as the node's policy lends the
same right to the principal `troupe:<name>`; that loan is the owner's
ceiling in "Nodes owned by someone else". `troupe join` asks all or none,
with no default. Concurrent writes of one version resolve by body hash, with
no coordinator, and the loser stays visible.

### Nodes owned by someone else

A troupe can admit a node another person owns, so they lend compute and their
figaros share the namespace. Gluck, 2026-10-18:

- Every node has an owner, the principal that joined it, recorded in its join
  entry.
- On a node, its owner's local policy is the ceiling. A grant from the troupe
  policy applies there only as far as that owner delegates to the troupe. Gluck's
  own nodes delegate everything; a guest node delegates what its owner chooses:
  who may create figaros on it, who may talk to figaros already there, and who
  may set ACLs on them.
- Nothing lets a guest owner create figaros on the troupe's other nodes unless
  the troupe policy grants it, and by default it does not.
- A guest owner sets ACLs on their own figaros in the shared namespace; the
  troupe can grant them access on other nodes like any principal.
- Figaros homed on a guest node are reachable only while it is online.

Several people on one node is the same mechanism with no guest node:
issuer-scoped principals (step 5) and the troupe or local policy (step 6).

## 5. Identity

- Humans authenticate to the issuer, and the token travels to whichever node
  owns the aria (F2), which re-verifies it. Principals are always scoped by
  their issuer, even in a troupe that trusts one (`user:jack@auth.kelliher.info`),
  so adding a second issuer renames nothing. Groups are scoped the same way
  (`troupe-members@auth.kelliher.info`), so a second issuer cannot hand out a
  group a binding meant for the first. The scope is the issuer URL without
  its scheme, never configured. (Built in step 5; agreed 2026-10-19, changing
  draft 4's "scoped when it trusts more than one".)
- `[authz.bearer]` became `[[authz.issuers]]`, read from local config. The
  troupe policy (step 6) carries troupe-wide issuers; for one URL in both,
  the local entry wins.
- One-user troupes are the default: the account that creates the troupe is
  bound as owner, and owner holds every grant, `join` included. On each
  machine, `troupe join` writes the peercred map so the local uid is the same
  principal everywhere: `[authz.peercred] uids = { 1000 = "user:jack@auth.kelliher.info" }`.
- Word handles (v0.46) are minted unique troupe-wide (one-hop peer check), so a
  handle names one aria anywhere in the troupe.
- Sandboxes and services get client-credential identities from the same
  issuer (S1), so a sandbox on any node is the same principal everywhere.
- Groups come from userinfo, never from token claims (the Authelia lesson).

## 6. Login and join

No approvals and no invites. Permission decides.

- `figaro troupe login <name>` authenticates the human (or a service) to the
  troupe. Schemes plug in: `oidc-device` first, `api-key` second.
- `figaro troupe join <name>` is a wizard that writes configuration: the troupe
  file, this node's door, and a request to the provider to sign this node's
  certificate. The provider signs only if the logged-in principal holds `join`
  on the troupe in the troupe policy (for example the group `troupe-members`).
- Writing the configuration by hand is equivalent; `join` saves typing.
- The provider's calls ride the figaro door: `troupe.sign`, `troupe.members`,
  `troupe.identity`.

## 7. Config and verbs

```
~/.config/figaro/troupes/<name>.toml    provider, door URL, auth scheme, issuer
figaro troupe login <name>              authenticate to the troupe
figaro troupe join <name>               wizard: write config, get this node signed
figaro troupe ls                        configured troupes, signed in or not, members
figaro troupe leave <name>              drop this node
figaro provider login|logout|ls         model credentials (0.45 rename)
```

`endpoints/` folds into `troupes/`: an endpoint is a troupe's door as seen by a
CLI.

## 8. Running as the user on a machine

Two modes, per node:

- **user mode** (today's gluck): the daemon is the user. Arias homed here run
  tools as the user under `sandbox:local`, granted by local policy only.
- **service mode** (spain, infra boxes): the daemon runs as its own uid. A
  user-mode figbox agent (S2) runs as the user's systemd user service, admits
  only the local daemon, applies the user's own policy, and runs tools as the
  user. Stopping it revokes.

A figaro homed elsewhere that needs to act on this machine uses the remote
sandbox provider (S2) into this node's figbox, or is moved here (F3).

## 9. Decided

- `leave` is a revoke the node signs about itself; an offline node lapses by
  certificate expiry.
- No policy merge on join.
- Troupe policy changes by an `admin` principal through any node; the root is
  for creation, intermediates and recovery only.
- A lost node loses its arias; tolerated for now.

## 10. Build order

1. `Membership` interface; static `[peers]` behind it, with a version compared
   on the handshake and drift in `troupe ls`. No other behaviour change.
2. Done in 0.45: `provider login`, `troupe login`, `troupes/`, `troupe ls`.
3. Troupe keys: `troupe create` (root via `op read`), per-node intermediates,
   short-lived node certificates, renewal. Prove with two dev roots, then gluck
   plus spain2.
4. Built: the `figaro` provider (`[troupe] provider = "figaro"`):
   `troupe.sign/identity/entries/leave`, `troupe join` (wizard plus peercred
   map) gated on `join`, membership as a gossiped union of signed entries
   kept in a form, `leave` and root revoke. Joined nodes are leaf-only (see
   section 3); a node holding an intermediate signs its own join, which marks
   it as a signer.
5. Built: `[[authz.issuers]]`; principals and groups always issuer-scoped.
6. Built: the troupe policy (admin-changed, node-signed, versioned, issuers
   included), the delegation ceiling, `sandbox:local` and troupe admin
   local-only, and quiet and lapsed members in `troupe ls`. Per-aria ACLs
   (a guest setting access on their own figaros) come after step 7.
7. Built: the `api-key` login scheme. Keys are troupe-issued principals
   (`service:<n>@troupe:<troupe>`), minted by an admin, hashed in signed
   ledger entries naming the nodes they are good on (never sent to
   another), revocable by minter, holder or admin, expiring within a year;
   `troupe login` seals the key with hush, or `key_file` names one.
   Upstream doors (spain's) wait on an edge pass-through.
8. Service mode with the user agent arrives with figbox (S2).
