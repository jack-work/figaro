## What it is

Spain's config declares a pool of slots. In v1 a slot is a name, a
generation, a ledger row and an authz subject: there is no container
behind it. herald, as its own principal on the web door, asks the daemon
for a lease on behalf of one Telegram group. The daemon picks a free slot,
gives it a name that has never existed before (`slot3-g7`: slot 3,
generation 7), mints one figaro pinned to that name, and answers. From then
on herald pushes group messages in with `figaro.slot.deliver` and the
figaro speaks out with its `telegram` tool, which the daemon relays to
herald. On release the daemon deletes the figaro and closes every
credential the lease held.

Four methods, two new verbs:

| method | who | verb on resource |
|---|---|---|
| `figaro.slot.lease {pool, key}` | herald | `lease` on `pool:<pool>` |
| `figaro.slot.release {pool, key, generation}` | herald | `lease` on `pool:<pool>` |
| `figaro.slot.deliver {pool, key, generation, id, text}` | herald | `lease` on `pool:<pool>` |
| `figaro.slot.say {text}` | the leased box, in-process only (D1) | `say` on `lease:self` |

herald's whole grant for groups is `lease:pool:telegram-groups`. It never
holds an aria id, a role or a box as a handle: the lease answer names them
for the record, and no grant of herald's reaches them.

## One fact that shapes the rest

A figaro's turn loop and its provider calls run in the daemon. A box only
runs tools that execute (bash, process, the file tools). The group outfit has
none of those, so **nothing executes in the slot box**. The `telegram` and
`brave` tools run in the daemon.

D1 follows from that: a leased box gets no door and no exec socket. El
Inspector then agreed that v1 needs no container at all, on conditions (a)
to (e), folded in below. His sentence (e):

> The day a pool gets an executing tool, containers, door, exec, the reset
> with nonce and probe, and figaro_claim all come back together in one
> change, for El Inspector's read.

(b): any exec dial for a leased box fails closed. The figaro's
`system.sandbox` names a box that has no socket, so a forged call to a tool
that executes is refused as not registered, and would fail at the dial if
it got further.

What the box still is:

- The principal. `sandbox:slot3-g7@local:box` is the subject the daemon
  builds when the figaro's `telegram` tool calls `say`, and the `minted_by`
  of everything in the lease. No listener stamps it, and no issuer, api key
  or troupe can mint that scope.
- `system.sandbox = "slot3-g7"` takes the figaro out of `unboxed`, so no
  troupe loan and no `unboxed` grant reaches it, and pins it.
- The leased box's `outfits` and `providers` lists apply by the rules that
  exist today.

B1 asked for `figaro_claim = "required"` on the slot box. With no door there
is no route on which a claim could be missing: the only caller is the tool,
in-process, and it always carries its figaro's claim. `say` checks it.

## Config: per slot. Principal: per lease.

```toml
[slot.pools.telegram-groups]
enabled             = true
outfit              = "herald-group"
provider            = "rou2"
rou2_lease_class    = "telegram-group"
say_url             = "<herald's group say endpoint>"
successions_per_day = 4
page                = "@<an owner role>"
brave_credential    = "brave-groups"      # a file in $CREDENTIALS_DIRECTORY

slots               = ["slot0", "slot1", "slot2", "slot3"]
```

(a): a slot is a name and nothing else. A pool whose slot carries an
`exec`, `door` or `reset` path does not load. (d): the number of slots
still bounds concurrent leases, which bounds spend and memory.

A slot is not a `[sandbox.boxes]` entry and has no principal. The mapping:

| | where it lives | lifetime |
|---|---|---|
| slot `slot3` | config, from nix | until the next switch |
| generation `7` | the lease ledger | rises by one per lease, never reused |
| leased box `slot3-g7` | the daemon's leased-box table, in memory, rebuilt from the ledger | one lease |
| principal `sandbox:slot3-g7@local:box` | `minted_by` in the store; the subject of an in-process `say` | one lease |

At lease the daemon adds `slot3-g7` to a leased-box table that
`config.Loaded.Box` consults after the config:

```
slot3-g7 = { outfits = ["herald-group"], providers = ["rou2"], purge_grace = "0" }
```

It has no `exec` and no `door`. Every rule that keys on a box name
(`sandboxed:self`, the outfit and provider lists, forms held in a box, a
role in a box pointing only inside it) then holds for the lease with no
change. The door machinery of v0.65.3 (#93) takes its wanted set from the
config's boxes only and never sees this table.

The generation is what makes R1 hold. `owner:self` reads `minted_by`, and
the lease's figaros are minted as `sandbox:slot3-g7@local:box`. No later
principal has that name, so nothing g8 does can match what g7 minted. The
counter never goes back:

- The ledger writes the new generation and fsyncs before anything is minted.
- If the ledger is lost, the next generation is one more than the highest
  found in any `system.sandbox`, any `minted_by` and any tombstone for that
  slot.
- rou2 is a second witness: it refuses to open a lease id it has
  tombstoned, and the daemon then takes the next generation and tries
  again.

Config rules, checked at load and at `angelus.configure`:

- A `[sandbox.boxes]` name of the shape `<name>-g<digits>` is refused, so no
  static box can collide with a lease. This is a breakage for any existing
  box named that way (spain has `box0`, `chat`, `receipt`: none).
- A pool whose outfit is `default`, is missing, or fails the outfit check
  below does not load, and its leases are refused.

## The provisioner (R2)

The provisioner is code in the daemon: the `lease`, `release` and
succession handlers. Today an in-process call is the owner and holds
everything. The provisioner does not use that.

**Principal.** `service:provisioner@local:pool`. `local:pool`, like
`local:box`, is not a host: no listener admits it, no issuer, api key,
peercred map or troupe policy can resolve to it, and a policy file that
binds it is refused at load. It arises only inside those three handlers,
which swap the context's subject to it before they touch the store, and
every inner call goes through `authz.Enforce` as that subject. A bug that
names the wrong aria is then refused by the guard, not carried out with the
owner's authority.

**Grant, per call (D2).** The subject carries the id of the one lease the
handler is serving, and the grant is computed for that lease alone, never
read from a policy file and never the union over live leases. With box `B`:

| permission | what it is for |
|---|---|
| `use:sandbox:B` | dress a form into the leased box |
| `create:sandbox:B` | a birth whose dressed form says `system.sandbox = B`, and nothing else (D3) |
| `set:sandboxed:B` | cast the lease's role, at lease and at succession; unset `system.succession_failed` when the succession window reopens |
| `kill:sandboxed:B` | delete the lease's figaros and forms at release |

`sandboxed:<name>` is the named spelling of `sandboxed:self`; only the
computed grant uses it. A provisioner subject with no lease, or a lease not
in `minting`, `live` or `releasing`, holds nothing. During lease A's mint a
provisioner call against lease B's figaro is refused.

D3: `create:*` and the default box role's `create` keep today's meaning. The
decision grid's golden output is identical except for the new verbs and
selectors.

Shape rules the grammar cannot say, enforced in the one mint function:

- Outfits are exactly `[pool.outfit]`. The lease request has no outfit
  field, and a request with any field beyond `pool` and `key` is refused
  (strict decode), so a caller that sends one learns it was not ignored.
- The birth patch is exactly `system.sandbox = B`,
  `system.scopes = ["say:lease:self"]` and `system.retirement.page` from
  the pool. The protected keys are written once, at birth, and no later
  `set` touches them.
- `minted_by` is `sandbox:B@local:box`.
- The slot is `free`, which it becomes only when the release of its last
  lease ran to the end (see the wipe), or the mint does not start.

D7: `system.succession_failed` and the mint-written
`system.retirement.page` are writable only by the owner or the provisioner.
The leased box's principal and the figaro itself cannot unset
`succession_failed` to escape the succession bound.

**What herald cannot do.** `lease:pool:telegram-groups` allows the three
methods and nothing else. `lease` is not `create`, `set`, `send`, `read` or
`use`, and no selector herald holds names an aria. The methods take no aria
id, so there is nothing to point elsewhere.

`lease` and `say` are local-only: a troupe policy cannot lend them, and a
call that arrives through the node door is refused.

## Grant grammar

With decide-narrow (b193e907), which adds the verb `decide` and the
selector `outfit:<name>`, herald's policy on spain reads:

```toml
[roles.herald-decide]
permissions = ["decide:outfit:herald-decide"]
[roles.herald-groups]
permissions = ["lease:pool:telegram-groups"]
[[bind]]
role = "herald-decide"
principals = ["<herald's machine client>"]
[[bind]]
role = "herald-groups"
principals = ["<herald's machine client>"]
```

New here: verbs `lease` and `say`, selectors `pool:<name>`, `lease:self` and
`sandboxed:<name>`. The verb ends at the first colon, as now.

The leased box's role is also computed, not configured: exactly
`say:lease:self`. A lease principal is judged only by that. A policy-file
binding that would match it (a name, or the kind wildcard `sandbox:*`) does
not apply to a name in the leased-box table. The default box binding
(`create`, `use:sandbox:self`, every verb on `sandboxed:self`) does not
apply either. With no door (D1) the principal reaches the guard only from
the in-process `say`; the role is what the guard would answer if it ever
arrived another way. The figaro's own `system.scopes` is the same single entry, so
the principal and the figaro's effective set both have to allow a call, and
both allow one thing.

Adding verbs means `*:*` now includes them and `figaro.scopes` spells two
more verbs out for a `*` entry. Nothing on disk changes meaning.

## Lease

`figaro.slot.lease {pool, key}` answers
`{pool, key, generation, box, aria, role, say_bearer}`.

1. Guard: `lease` on `pool:<pool>`. Pool disabled: refused, `pool_disabled`.
2. A lease for `(pool, key)` by this principal that is `live`: answer it
   again, same generation and same bearer. `releasing`: refused with
   `releasing` and a retry hint. Held by another principal: `no_such_lease`.
3. Pick a `free` slot. None: `pool_empty` (below).
4. Ledger: `minting`, generation + 1, fsync.
5. rou2: open the lease's caller (B4).
6. Add the leased box to the table.
7. As the provisioner: mint the figaro, mint the role (a form held in the
   box, `target-aria` the figaro), place both under the pool's node in
   `@topology`.
8. Mint the 256-bit say bearer. Ledger: `live`, fsync. Answer.

A step that fails rolls the lease into the release path and answers the
error. A crash in `minting` is never completed after restart: recovery
releases it, and herald's retry gets a new generation. herald never saw the
old one.

**Pool empty.** One error code for the family (the next free after -32020;
fixed at build) with `data.reason`. `pool_empty` carries
`{pool, slots, leased, releasing}` and `retry_after` when a slot is
mid-release. herald refuses the join, leaves the group and logs the
group id (R4). The daemon logs one warn line and counts it, so growing the
pool is a decision made from a number.

## Deliver and say

`figaro.slot.deliver {pool, key, generation, id, text}`. The daemon finds
the lease by principal, pool and key, refuses a generation that is not the
live one (`stale_generation`, with no word about the current one), and
queues `text` as a prompt to the role's holder. Succession is invisible to
herald. `text` is opaque: herald renders the sender block (H3). The answer
is `{queued: true}`; herald gets no stream and no `listen`.

`id` is herald's message id. It is written on the input message in the same
store append as the prompt, and the dedupe index for `(key, generation, id)`
is rebuilt from the lineage's inputs when the figaro wakes, so a retry after
a daemon restart neither doubles nor loses a message. Size is capped
(`deliver_max_bytes`, default 16 KiB). herald's per-group limit (H9) comes
first; the pool holds a hard ceiling behind it.

`figaro.slot.say {text}` is served in-process only (D1): no door carries
it. The `telegram` tool calls it through `authz.Enforce` as the lease
principal with its figaro's claim. The daemon looks up the lease from the
principal, checks the claimed figaro is in that lease's lineage and not
retired (a claim for another lineage is refused), and POSTs
`{key, generation, text}` to the pool's `say_url` with the lease's bearer.
herald keeps only the bearer's SHA-256 against route and generation and
drops it at release (R3). The bearer lives in daemon memory and the ledger
(mode 0600; the `@slots` view omits it) and never enters the box. A 4xx from
herald is the tool's error and is not retried.

Rejected: `send:role:@<role>` for herald on `figaro.qua`. It also grants
attach, interrupt and queue edits, and puts an aria handle in herald's
hands. Rejected: a credential file written into the slot. It is a secret in
the one place an untrusted group steers.

## The outfit (H6) and the tools (B2)

`herald-group` is a file in spain's outfit directory, from nix. The pool
names it; the request cannot.

```toml
# outfits/herald-group.toml: no layers
credo = "<a short group brief>"

[system]
provider = "rou2"
model    = "explabs/gpt-6.1-sol"
tools    = ["brave", "telegram"]

[system.retirement]
context_threshold = "50%"
action            = "succeed"
ttl               = "0"
```

`system.tools` is exactly `["brave", "telegram"]`.

At pool load, and again at every mint against a pinned hash, the folded
outfit is refused if it has: a layer; any `skills.*` key; any leaf named
`filePath`; `system.cwd`; `system.environment`; `system.methods`;
`system.studies`; `system.decide.*`; a `system.retirement.ramp` that names a
file; or a `system.tools` that is not a subset of the pool's two tools.
Bundled skills arrive only through an outfit's `skills = { dirName }`
loader, so an outfit with no `skills` key carries none. A create that names
an outfit dresses in that outfit alone: `default` is used only when none is
named. The leased box's `outfits` list holds this one name. `system.tools`, `system.model`,
`system.provider`, `system.credo` and `system.retirement` are owner-held,
so nothing but the owner changes them after birth.

Two fences on tools:

1. The registry. A figaro whose sandbox is a leased box gets a registry with
   the pool's tools only. `bash`, `process`, `read`, `write` and `edit` are
   not registered, and a leased box has no exec socket to open.
2. `system.tools`, checked where tools are offered and where a call runs.

| tool | arguments | what the daemon does | limits |
|---|---|---|---|
| `telegram` | `text` | `figaro.slot.say` as the lease | 4096 characters, `say_per_minute` |
| `brave` | `query`, `count` up to 10 | one GET to Brave's search API on a fixed host, no redirects, with the pool's key; returns titles, URLs and snippets as text | `brave_per_minute`, `brave_per_day`, a size cap on the body read and on the result |

The Brave key (D6) is a systemd credential that Gluck types. The daemon
reads it at call time and keeps it in no form, log, span, tool result or
error string: an upstream error reaches the model as its status code, never
its body.

What B2 asks, row by row:

| reach | why not |
|---|---|
| Gluck's data, the host filesystem | no file or exec tool is registered; no path in the form; the box has no socket to execute through |
| other arias, forms, roles | the principal's whole grant is `say:lease:self`, and so is the figaro's scope |
| hush | no tool reaches it; the Brave key is a systemd credential read by the daemon, the say bearer and the rou2 lease are daemon-held |
| the network | the daemon makes two kinds of call for it: herald's say URL and Brave search. The model chooses the text and the query, nothing else |

Residual: a guest can make the figaro send group text to Brave as a query.
That is the group's own text going to a search engine.

## rou2 caller and cap (B4)

El Aduanero's interface (rou2 side, his to build, El Inspector pre-reads):

- `POST /v1/leases {id, class}` as client `figaro` answers
  `{id, class, caps}`. `id` is `telegram-groups/slot3-g7`. `class` names a
  template in rou2's config (`lease_classes.telegram-group`: rate per
  minute, tokens per day, USD per day, USD total, upstreams `[explabs]`,
  models `[gpt-6.1-sol]`). Neither herald nor figaro can raise a cap.
  Idempotent for an open id with the same class.
- Every provider request for a figaro of the lease carries
  `Rou2-Lease: <id>` beside the daemon's bearer. rou2 admits it only if
  that client opened the lease and it is open. Caps, usage and the caller
  label are the lease's.
- `DELETE /v1/leases/<id>` closes it for good. A closed id is tombstoned
  and can never reopen, so g8 inherits nothing. `GET /v1/leases` lists open
  ones for reconcile.
- Refusals: a windowed cap is 429 with `Retry-After`, header `Rou2-Cap` and
  `{error: {type: "rou2_cap"}}`; the lifetime cap is 403
  `rou2_cap_exhausted`; a closed or unknown lease is 403 `lease_closed` or
  `lease_unknown`; a model or upstream outside the class is 403
  `lease_scope`.

Figaro's side: the provider request builder looks up the lease from
`system.sandbox` and adds the header. A figaro in a leased box with no open
rou2 lease does not send. `rou2_cap` is not retried inside its window, and
the turn fails with the cap named. `rou2_cap_exhausted` and `lease_closed`
make the lease dormant and page the pool's `page` role.

"The box's own caller" is therefore a lease id that rou2 registered and can
close, presented by the daemon, since the box is a name and makes no call.

## Succession (H5)

The outfit sets `system.retirement` to succeed at 50%. retire-succeed
(0ae0e864) owns the mechanism. For a figaro in a leased box the pool is the
successor's minter, through a seam that lane has to offer:

- Same mint function as the lease: same box, so the same claim rule; scopes
  restamped, not copied; the pool's outfit, never a role's
  `succession-policy.outfit`; `minted_by` the lease principal.
- Same rou2 lease, since the header is chosen by `system.sandbox`. A whole
  lineage spends one cap.
- The provisioner recasts the lease's role. The old figaro is purged when
  the successor's first turn ends, so a lease holds at most two figaros.
  Today `completeSuccession` retires with `retirement.ttl`; the purge is a
  change there for leased figaros.
- `successions_per_day` (4) is counted in the ledger over a rolling 24
  hours, and it counts attempts, so a mint that fails is not free.
- At the bound the pool's minter refuses. retire-succeed treats that as a
  mint failure: the old figaro stays unretired, `system.succession_failed`
  is set and holds off any retry, and the page goes out. An unretired
  figaro past its threshold must not keep taking turns, so the pool marks
  the lease dormant and `deliver` answers `dormant` with `retry_after`.
  The first deliver after the window reopens has the provisioner unset
  `system.succession_failed`, which lets the owed succession run, and is
  queued behind it. herald decides what the group is told.
- The ramp brief is retire-succeed's inline text. It points at `ramp.md`
  only when `system.retirement.ramp` is set and names a handoff path only
  when a role carries one; the outfit check refuses the first and the
  lease's role never carries the second. Both would be host paths, and the
  figaro has no file tool. The successor reads the last turns, quoted by
  the daemon.
- `page` is a field of `system.retirement`; the mint writes the pool's
  `page` there, so a failure never pages a drawn parent. The page carries
  ids and the reason, never transcript text.

A guest who fills the context buys at most four fresh figaros a day, each
paid for from the group's one cap.

## Release (B5, H1)

`figaro.slot.release {pool, key, generation}`. The generation is required:
it is what stops a delayed retry for g6 from touching g8 after the group was
re-added. A release for a `(key, generation)` already released answers ok
(the ledger keeps released rows, bounded); an unknown one is `no_such_lease`.

herald revokes the route's say grant first (H1), then calls. The daemon:

1. Ledger: `releasing`, fsync. From here `deliver` and `say` for this
   generation are refused.
2. Interrupts the turn and stops the agent.
3. Drops the say bearer. Closes the rou2 lease.
4. Removes the leased box from the table. The principal now has no grant.
5. Purges, with no grace, every figaro and form of the lease: the ledger's
   list, plus a scan for `system.sandbox = B` or `minted_by = sandbox:B`.
6. Marks the slot `free`. Answers herald.

H1 says spain stops and removes the box. In v1 removing it is step 4:
there is no process to stop.

Each step is safe to run twice, and recovery resumes at the first undone.
A step that cannot finish (rou2 unreachable, a purge error) leaves the slot
`releasing`, retried on a timer and logged; it is not offered meanwhile.

**Deleted, not dormant.** The choice the brief asks for:

- The transcript is other people's messages. herald itself keeps only
  lengths and ids for group routes (B7); a daemon that kept the text would
  make that promise false.
- Keeping it needs an owner, and `minted_by` is written once at birth and
  rewritten by nothing. Re-owning is a new authority-changing write.
- A kept transcript is readable by every `*:*` holder and sits in every
  backup from then on.
- Nothing reads it. The group's history is in Telegram.

If Gluck later wants transcripts kept, that is a pool key
(`keep_transcripts`) plus the re-own at teardown, for El Inspector's read.

What outlives a release: tombstones (ids, `minted_by`, ancestors; no text),
the ledger's released row, rou2's usage lines under the closed lease id, and
log lines carrying ids.

D4: "deleted" is a claim about bytes, and it is not yet proven. The canary
check covers everything the daemon writes: node directories, the turn wal,
translation channels, xwal and figwal segments, the ui and freeze caches,
`logs.jsonl`, traces, metrics, and figscope's store on spain. This lane did
not read the purge path. The build's first task is to find whether any
shared append-only file still holds a purged figaro's text; if one does,
the build names the compaction that removes it, and until that exists the
note's word is "unreferenced", not "deleted". Spans and logs for a leased
figaro carry ids, lengths and counts only.

D5: backups exclude leased figaros (any node whose `system.sandbox` names a
pool slot). If the backup tool cannot, the residue is accepted in writing:
the retention is named and the group brief says so in one line.

**The wipe (c).** With no container the wipe is the purge plus the closure
of every credential. Carriers of state from one lease to the next, and what
ends each:

| carrier | ended by |
|---|---|
| the principal and everything it minted | the generation; the purge |
| say bearer | dropped by the daemon, hash dropped by herald |
| rou2 caller and caps | lease closed and tombstoned in rou2 |
| the figaro, its role, its forms | purged; the D4 canary check |
| the agent in daemon memory | stopped at step 2 |

A slot returns to the pool only after all five. There is no reset, receipt
or probe in v1, and no keel sandboxes delta.

**Kill switch.** Three triggers, one drain:

- herald's `groups off` revokes every say grant, then releases every lease.
- `enabled = false` on the pool (or the pool removed) and
  `angelus.configure`: `lease`, `deliver` and `say` are refused from that
  instant, then every lease is released. This does not need herald.
- `figaro slot drain <pool>` (admin), the same from the CLI.

Unbinding herald's grant stops new leases and delivers but drains nothing;
the note says so in case anyone reaches for it as the switch.

## Restart recovery

The ledger is the truth, read before any door serves a pool method.

- `live`: leased box re-added to the table. The figaro stays dormant until
  a deliver.
- `minting`, `releasing`: run the release path from the first undone step.
- rou2 reconcile: an open rou2 lease with no live ledger row is closed; a
  live row with no open rou2 lease is released.
- Orphan scan: any figaro or form whose `system.sandbox` is `<slot>-g<n>`
  for a pool slot with no live lease at that generation is purged.
- A slot that left the config while leased: that lease is released.
- Ledger lost: generations from the floor rule above, every slot's figaros
  purged, every open rou2 lease of this daemon closed. herald's next deliver gets `no_such_lease` and
  herald leases again or leaves; the conversation is gone either way.

## Test plan

Each row has a canary: the same test with the fence removed has to fail.

| claim | test |
|---|---|
